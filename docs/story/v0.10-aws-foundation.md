# v0.10-aws-foundation: the AWS foundation

**Goal (plan v0.10).** Terraform for the AWS foundation: a greenfield VPC whose private subnets
are placed by **AZ ID** (AgentCore VPC mode accepts only `use1-az1`, `use1-az2`, `use1-az4`),
one NAT gateway, flow logs, the interface endpoints the WCI and the Worker need, an S3 gateway
endpoint, four security groups, the Route 53 private zone; then EKS with IRSA, the VPC CNI
network-policy agent, arm64 nodes, the AWS Load Balancer Controller and cert-manager, RDS
PostgreSQL 16 with TLS forced, the two application IRSA roles and ECR.

> **Status: done (2026-10-31).** Applied in us-east-1 (go-ahead G5) and **left running** for
> v0.11, as the user asked. `scripts/verify/v0.10-aws-foundation.sh`: **OK** (63 checks); the
> second plan of all four stacks shows **No changes**; `make check` green. Nothing was paused or
> destroyed; pause, resume and destroy were only dry-run.

## Deviations

- **PostgreSQL 16.15, not 16.6:** RDS no longer offers 16.6 (ADR-0006, ledger 38 fallback).
- **SG names** are `agentcore-demo-<role>`, not `sg-<role>`: AWS does not allow a group name to
  start with `sg-`. The runbook name is the `Role` tag.
- **SG rule descriptions** cannot contain `>` (the first 10-network apply failed on three rules
  with `Invalid rule description`; fixed to "to", re-planned, the 3 rules applied).
- **S3 gateway endpoint policy left at full access**, not only the `acr-code-*` statement: a
  gateway endpoint applies to all S3 traffic from the private subnets, and ECR layer and quay.io
  blob downloads that land on S3 in us-east-1 would break. v0.12 (AWS Q2) can narrow it.
- **Interface endpoints in 2 AZs**, not all private subnets (cost; ADR-0006).
- **No customer KMS key** for EKS secrets (EKS default envelope encryption; ADR-0006).
- **`rds.force_ssl` declared with `apply_method = "pending-reboot"`**: with `immediate` the
  second plan showed drift (RDS reports a default-valued parameter that way). Changed in code;
  the following plan was clean without another apply.
- **Node count 2** (plan: 2–3): `max_size` 3 for v0.11 if Temporal needs it.
- **Tags** `Project=agentcore-self-hosted` / `Stack` / `ManagedBy` (as since v0.8), not the
  plan's `project=temporal-customer-support`.
- The verify script needed four fixes before it passed (container name `aws-eks-nodeagent`,
  `pg_stat_ssl.ssl` prints `true`, `current_setting('rds.force_ssl')` is not available, the
  expected `AccessDenied` exits non-zero), and `tf.sh`'s 20-platform destroy guard skipped
  itself under `pipefail` (fixed; its dry run then printed "guard ok").
