# v0.4-finance-agent: another team's agent, behind a published A2A contract, reached over Nexus

**Goal.** Team Finance publishes exactly one thing, an A2A-shaped contract
(`finance_a2a_api`). Behind it, in namespace `agent-services`, runs the **Finance
Refund agent**: a Nexus service handler (`FinanceAgentA2AHandler`) and one Workflow
per A2A task (`FinanceAgentTaskWorkflow`). Nothing on the caller side uses an LLM
yet: a plain Workflow in namespace `agents` (`A2ASmokeWorkflow`) calls the named
endpoint `finance-agent`, and the Temporal server routes the call into the other
namespace.

**Why now.** The handler comes before the caller (runbook 10.9). Wiring Nexus
separately from LLM behaviour means a failure in v0.5, when the Supervisor calls
Finance from inside its agent loop, can only be the plugin or the prompt. It can't
be the endpoint, the namespaces or the contract.

> **Status at hand-off: offline complete and verified; one live Bedrock run pending
> (justified deviation, same cause as v0.2 and v0.3).** `aws sts get-caller-identity`
> still returns `InvalidClientTokenId`, and `aws sso login` needs a browser. With the
> real model, `make dev` + `make smoke` shows the designed failure path: the Finance
> task ends `failed` with "Risk assessment failed: TokenRetrievalError: … Token has
> expired and refresh failed" after the bounded model retries. The live run is
> `scripts/verify/v0.4-finance-agent.sh` without `VERIFY_SKIP_BEDROCK` (two small
> model turns per A2A task), added to ledger item 49. The v0.4 questions (Q16, Q21,
> A2A field names, Nexus and time-skipping, the 10 s limit) don't depend on the model,
> and all of them are answered offline against a real dev server.

## Which samples and docs it follows

- **samples-python**
  - `hello_nexus/service.py`: the contract is plain dataclasses plus a
    `@nexusrpc.service` class of `nexusrpc.Operation[In, Out]` attributes, which both
    sides import.
  - `hello_nexus/handler/service_handler.py`: `@nexusrpc.handler.service_handler(service=…)`,
    `@nexus.workflow_run_operation` returning `ctx.start_workflow(...)`, and
    `@nexusrpc.handler.sync_operation` for the quick one ("must not exceed 10s").
  - `hello_nexus/handler/worker.py`: a Worker with `workflows=[...]` and
    `nexus_service_handlers=[Handler()]`; the connection comes from envconfig with a
    namespace default.
  - `hello_nexus/handler/workflows.py` and `caller/workflows.py`: the contract imported
    through `imports_passed_through()`, and `workflow.create_nexus_client(service=…,
    endpoint=…)` built in `__init__`, then `execute_operation` in `run`.
  - `nexus_multiple_args/handler/service_handler.py`: a deterministic Workflow ID built
    from the input (here `a2a-task-<context_id>`).
  - `hello_nexus/endpoint_description.md` and its README: the endpoint description is
    markdown passed with `--description-file`. Ours is the Agent Card.
  - `tests/hello_nexus/hello_nexus_test.py` and `tests/helpers/nexus.py`: create the
    endpoint through the operator service per test module and delete it afterwards.
    Our helper adds the target namespace (cross-namespace) and the description.
  - `nexus_standalone_operations`: client-side `create_nexus_client(...).execute_operation(id=…)`
    and the CLI `temporal nexus operation` commands (Q16).
  - `strands_plugin/tools/workflow.py`, `bedrock_agentcore/strands_agent`: the Finance
    agent is built in the Workflow, its Activities are `activity_as_tool`, and it runs
    with `invoke_async`. `tests/strands_plugin/tools_test.py`: plugin appended through
    `client.config()`, `max_cached_workflows=0`.
  - `message_passing` and `strands_plugin/human_in_the_loop`: the query over Workflow
    state (`get_task`).
- **temporal-developer skill**
  - `python.md`: Workflows and Activities in separate files; `@workflow.init` when
    state depends on the input; sync Activities on a `ThreadPoolExecutor`;
    `ClientConfig.load_client_connect_config()`.
  - `gotchas.md`: pass-through imports; no blocking calls in async code; test failure
    paths and replay.
  - `testing.md`: shared `start_local` for most tests, time-skipping only where
    needed, `ActivityEnvironment`, a unique task queue and ID per test, replay from
    JSON.
  - `error-handling.md`: non-retryable `ApplicationError` for 400/409 from payments;
    transient errors retried by Temporal; idempotency key for the side effect.
  - `ai-patterns.md`: client retries off (botocore and httpx); Temporal owns retries;
    pydantic converter through the plugin.
- **Temporal docs** (searched with the docs MCP tool)
  - `NexusClient.execute_operation(..., summary=...)` (Python API reference) answered Q21.
  - The Standalone Nexus Operation pages and the server 1.32.0 release notes gave the
    CLI ≥ 1.9.0 requirement and the key `nexusoperation.enableStandalone` (Q16).
  - `WorkflowEnvironment.create_nexus_endpoint` targets only the environment's own
    namespace, so we wrote our own helper for the cross-namespace endpoint.
  - The SDK source was read for anything the docs didn't settle:
    `temporalio/nexus/_operation_context.py` (the request ID and
    `on_conflict_options.attach_completion_callbacks` behind `USE_EXISTING`) and
    `nexusrpc.HandlerError`.

## Run it

```bash
make setup                      # once
make dev-server-up              # agents + agent-services, standalone Nexus ops on
make payments-mock &            # :8081
make worker-finance-scripted &  # offline; `make worker-finance` uses Opus 5.5 (needs aws sso login)
make worker-smoke &             # A2ASmokeWorkflow on nexus-smoke-tq (no LLM)
make nexus-endpoint             # finance-agent -> agent-services/agent-services-tq, description = Agent Card
make card                       # standalone Nexus Operation from the CLI: get_agent_card
make smoke                      # smoke-1042: $40 -> completed, refund_confirmation
make smoke WF=smoke-2077 AMOUNT=450 ORDER=2077   # -> rejected (needs a Finance approver)
make task-state WF=smoke-1042   # get_task in agent-services
uv run python scripts/a2a_timeline.py smoke-1042
# or all at once: make dev   (honcho: dev server, payments-mock, Finance Worker (Opus 5.5), smoke Worker)
```

The plan's commands work as written:
`temporal nexus operation execute -n agents --endpoint finance-agent --service FinanceAgentA2A --operation get_agent_card --operation-id card-smoke --input '{}'`
and
`temporal workflow start -n agents -t nexus-smoke-tq --type A2ASmokeWorkflow -w smoke-1042 --input '40'`.

## Deviations and decisions

- **Live Bedrock not run** (AWS SSO session expired). This is carried as ledger item 49
  and is the first thing to do in v0.5. The real-model path was exercised up to the
  credential error: the task ended `failed`, as designed.
- **v0.4 is auto-approve only, as planned.** A request over $100 or at HIGH risk ends
  `rejected` with "needs a Finance approver; approvals are not enabled on this agent
  yet". v0.6 turns that branch into `input-required` plus signals. The Agent Card text
  ("need a human Finance approver") is true in both versions.
- **Finance data lives in `src/finance_agent/data/`**, not `services/finance-agent/data/`
  (plan §2.2), so it ships inside the package (`importlib.resources`), as Support's does.
- **`payments-mock` uses the stdlib only** (`ThreadingHTTPServer`), so the Docker image
  (v0.9) needs no dependencies.
- **Smoke caller input.** `A2ASmokeWorkflow.run(amount_usd, order_id="1042")`: the
  plan's `--input '40'` works unchanged, and a second input selects the order.
- **Q16 needs a dev-server flag.** `scripts/dev-server.sh` and the test fixture now pass
  `nexusoperation.enableStandalone=true`. kind and EKS (v0.9 and v0.11) must set the
  same dynamic-config key.
- **ADR-0004** records `USE_EXISTING` and the default reuse policy (a resend after close
  is a new run that moves no money).

## Talk track

"The Finance team publishes exactly one thing, an A2A-shaped contract: an Agent Card
and two operations. No AI on the caller yet, just the hop. A Workflow in `agents` calls
a named endpoint, `finance-agent`, and the server routes it into another namespace,
`agent-services`, where Finance's own agent scores the fraud risk and code, not the
model, decides whether money moves. Workers never talk to each other. Click the
`send_message` event and you jump into the other team's namespace, to the A2A task.
Send it twice and you get one task and one refund."
