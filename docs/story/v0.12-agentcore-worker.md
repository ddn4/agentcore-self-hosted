# v0.12-agentcore-worker: Support on AgentCore in VPC mode, invoked by the WCI on EKS

**Goal (plan v0.12).** Support runs on AgentCore Runtime in **VPC mode** as the serverless
Worker Deployment Version `support-supervisor:4ee7f87`, registered from `main` against the
Temporal server on EKS. The server's Worker Controller (WCI, worker service, IRSA role
`temporal-server-wci`) assumes the invocation role with the External ID and invokes the runtime.
A microVM in our VPC dials the frontend's Route 53 name over mTLS (client cert from Secrets
Manager), polls `support-tq`, does the work, drains after 30 s and goes away. Proof: a
PingWorkflow, then Case A, with **zero** other pollers.

**Result (2026-10-31): done.** `scripts/verify/v0.12-agentcore-worker.sh` → `verify: OK`.
Everything created here is **left running for v0.13**: the runtime and endpoint, the
invocation role, the registration (current version `4ee7f87`) and the mTLS secret.

The run in two sentences: the first attempt stopped at the Secrets Manager write (permission
policy) after the IAM step; once the user allowed `make export-agentcore-cert*`, the rest went
through, except that the first AgentCore session **could not reach the NLB** (cross-zone load
balancing off, ledger 70). One annotation fixed that, a re-registration recovered the WCI
(ledger 71), and ping and Case A then ran with nothing else polling.

## The NLB cross-zone finding (ledger 70)

The first registration succeeded on the Temporal side, and the WCI invoked AgentCore
(`InvokeWorkersToRegisterTaskQueues`). The session loaded the mTLS material from Secrets
Manager and then failed:

```text
19:24:33 INFO support_agent.mtls: mTLS: client cert, key and CA loaded from Secrets Manager into env
19:24:43 ERROR support_agent.agentcore: worker lifetime 1 failed
TimeoutError: could not connect to Temporal within 10s
```

Flow logs (raw records read locally, summarized here): the AgentCore ENI in one AZ sent 4
packets / 240 B to `:7233` of the **NLB node in a third AZ**; that node's ENI forwarded nothing.
The 2 frontend pods sit in the other two AZs, cross-zone load balancing was **off** (NLB
default), and the Route 53 alias hands out all three NLB IPs (`client_routing_policy
any_availability_zone`). A client that picks the empty AZ's node gets no answer. The v0.11 checks
started from pods in the two frontend AZs, so they never hit it. Fix: the LBC annotation from the
[LBC Service annotations guide](https://kubernetes-sigs.github.io/aws-load-balancer-controller/latest/guide/service/annotations/)
("enable cross zone load balancing", read 2026-10-31), `make eks-temporal`, attribute
`load_balancing.cross_zone.enabled = true` within seconds, no pod restarted. The NetworkPolicy
`temporal-frontend-from-nlb` already admits all three NLB ENI IPs, so nothing else changed.

## The WCI after a failed registration (ledger 71, ask Temporal)

Because the registration session never connected, `support-tq` never joined the version
(`describe-version`: `taskQueuesInfos: null`). The verify's ping-1 then waited **14 min** as an
unversioned task: WCI history only `PullStats` every 60 s, `InvokeWorker activities: 0`. The WCI
does not retry the registration. Recovery: `--unversioned`, `delete-version --skip-drainage`
(without it: "cannot be deleted since it is draining"), and once the old WCI instance had closed
(an immediate `create-version` failed "something went wrong, please retry"), a new
`make register-version`. That registration session connected, registered `support-tq` and, as a
bonus, picked up the waiting ping-1:

```text
ping-1  COMPLETED 19:47:44Z  "pong ping-1 from pid 343 on localhost [support-supervisor:4ee7f87]"
        versioningInfo: PINNED, support-supervisor.4ee7f87
```

The verify script then used a fresh ID (`ping-v012-…`) for the clean zero-poller probe.

## Rollback

1. `temporal worker deployment set-current-version --unversioned --yes`, then `delete-version --skip-drainage`.
2. `make agentcore-down`.
3. `make invoke-role-delete`.
4. Delete `temporal/agentcore-worker-mtls` with a 7-day recovery window.
5. Re-add the dev role only for a v0.8-style laptop WCI run (`create_dev_wci_role = true`).
6. Cross-zone: drop the annotation line and `make eks-temporal` (not recommended: ledger 70).
