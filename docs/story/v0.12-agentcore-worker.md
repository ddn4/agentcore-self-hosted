# v0.12-agentcore-worker: Support on AgentCore in VPC mode, invoked by the WCI on EKS

**Goal (plan v0.12).** Support runs on AgentCore Runtime in **VPC mode** as the serverless
Worker Deployment Version `support-supervisor:<Build ID>`, registered from `main` against the
Temporal server on EKS. The server's Worker Controller (WCI, worker service, IRSA role
`temporal-server-wci`) assumes the invocation role with the External ID and invokes the runtime.
A microVM in our VPC dials the frontend's Route 53 name over mTLS (client cert from Secrets
Manager), polls `support-tq`, does the work, drains after 30 s and goes away. Proof: a
PingWorkflow, then Case A, with **zero** other pollers.

> **Status: blocked (2026-10-31), partly applied.** The tooling is written, tested offline and
> committed (`eec55a7`, Build ID **`4ee7f87`**). In AWS, only step 2 (IAM) is applied. Step 1, the
> Secrets Manager write of the AgentCore Worker's mTLS secret, was **refused by the session's
> permission policy** ("Secret-Store Writes"). Nothing was worked around, and nothing after it
> was created: no runtime, no invocation-role stack, no registration. Terraform state is
> consistent (no saved plan left behind). The exact command and the resume steps are below.

## Offline evidence: the AgentCore CLI does VPC + named endpoint + existing role (ledger 42, synth half)

`TEMPORAL_BUILD_ID=0000000 MODE=VPC scripts/agentcore-deploy.sh build` (AgentCore CLI 1.0.1,
no AWS call). The first attempt failed in the CLI's own schema check because the bundle had
been rendered without the VPC inputs (`✖ Must be a subnet id (subnet-...)`), which is why
`build` now re-renders. The synthesized template (redacted):

  LifecycleConfiguration {IdleRuntimeSessionTimeout: 120, MaxLifetime: 28800}
  ProtocolConfiguration HTTP; Tags {agentcore:project-name: AgentcoreDemo, Project: agentcore-self-hosted}
  EnvironmentVariables  AGENTCORE_DEBOUNCE_SECONDS AGENTCORE_HOST AWS_REGION BEDROCK_EFFORT BEDROCK_MODEL_ID SUPPORT_GIT_SHA
                        TEMPORAL_ADDRESS TEMPORAL_BUILD_ID TEMPORAL_CONNECT_TIMEOUT_SECONDS TEMPORAL_DEPLOYMENT_NAME
                        TEMPORAL_MTLS_SECRET_ID TEMPORAL_NAMESPACE TEMPORAL_TASK_QUEUE TEMPORAL_TLS TEMPORAL_TLS_SERVER_NAME

So the control-plane fallback (`create-agent-runtime` + `create-agent-runtime-endpoint`) and
