# v0.8-wci-handshake: first AWS contact

**Goal (plan v0.8).** The dev server's Worker Controller Instance (WCI) assumes the self-hosted
invocation role, checks the External ID, resolves the endpoint and calls `InvokeAgentRuntime`
on a throwaway **PUBLIC** runtime (ADR-0005). A local versioned Worker of the same Build ID
makes registration succeed. Same-day teardown.

> **Status: done (2026-10-30, resumed run).** The first attempt stopped at plan step 2 (the
> `30-agentcore-iam` apply was refused by the session's permission policy; nothing was worked
> around). With project-local permission rules for the listed make targets, the run resumed at
> step 2 and went through step 9 the same afternoon: IAM applied, profile appended, PUBLIC
> runtime deployed, invocation-role stack created, the real WCI handshake observed in the
> WCI history, CloudTrail and the runtime's logs, registration and the negative test, the
> ping-1 probe, the Q15 probe (**yes**), and the teardown (runtime, CLI stack, invocation-role
> stack and the runtime's log groups gone, sessions back to 0).

## Why now

It moves the IAM, CFN, External ID, CLI and CodeZip risk ahead of any standing
infrastructure (plan v0.8). v0.7 showed its precondition holds: the dev server contains the WCI.

## Deviations

- The verify script no longer creates or deletes AWS resources (the first version deployed and
  tore down inside part 2). Every mutation is a reviewed make target; the script gates on what
  they created and checks the teardown in part 3.
- Registration used `update-version-compute-config`, not `create-version`: with the local
  Worker polling first, the version already exists (documented CLI behaviour).
- "Invoke count flat for 5 min after terminate" did not hold: 5 invokes in 4.5 min, then flat.
  Recorded, not hidden; `docs/ask-temporal.md` asks why.
- `delete-version` right after stopping the local Worker is refused ("active pollers");
  `set-current-version --unversioned` (plan: "or") succeeded at once, `delete-version` a few
  minutes later.
- `make agentcore-down` now also deletes the runtime's log groups (never-expire retention,
  left behind by AgentCore).
