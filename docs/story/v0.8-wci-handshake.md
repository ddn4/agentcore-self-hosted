# v0.8-wci-handshake: first AWS contact (blocked at the IAM apply)

**Goal (plan v0.8).** The dev server's Worker Controller Instance (WCI) assumes the self-hosted
invocation role, checks the External ID, resolves the endpoint and calls `InvokeAgentRuntime`
on a throwaway **PUBLIC** runtime (ADR-0005). A local versioned Worker of the same Build ID
makes registration succeed. Same-day teardown.

> **Status: BLOCKED at plan step 2 (the `30-agentcore-iam` apply).** The reviewed plan
> (4 creates: two IAM roles and their inline policies, nothing else) was refused by this
> session's permission policy ("protected-scope IaC apply"). Nothing was worked around: no
> role was created by any other means. Every later step needs those roles (the CFN invocation
> role trusts `temporal-dev-wci`; the runtime uses the execution role), so **no AgentCore
> runtime, no CFN stack and no WCI handshake ran.** What did run: the guardrails (step 0), the
> External ID secret and the vendored template (step 1), the CLI's packaging/synth of the
> PUBLIC probe, and every read-only answer below. Resume commands are at the end.

## Why now

It moves the IAM, CFN, External ID, CLI and CodeZip risk ahead of any standing
infrastructure (plan v0.8). v0.7 showed its precondition holds: the dev server contains the WCI.

## Talk track

"The Worker Controller ships inside the Temporal server, even the dev server. On AWS it
assumes a narrowly scoped role guarded by an External ID and starts an AgentCore session;
`create-version` is our self-hosted 'Validate Connection' button. Before any of that runs we
put a budget and a session alarm in place, keep the External ID out of Terraform state, and
let AgentCore's own CLI package the Worker: one `pyproject.toml`, arm64 wheels, 42 MB."
