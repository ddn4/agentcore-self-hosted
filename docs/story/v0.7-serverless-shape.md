# v0.7-serverless-shape: the Support Worker is built to die

**Goal.** The Support Worker in AgentCore Runtime shape, run on the laptop: a
`BedrockAgentCoreApp` whose entrypoint starts a versioned Worker in the background and
acknowledges at once; the Worker drains when idle and releases the session; every
conversation is **PINNED** to the content-hash Build ID it started on; the code ships as a
CodeZip bundle. No AWS.

**Why now.** It is the last purely local tag. Everything the AgentCore Worker contract
asks of our code (runbook §1.2 steps 4–6, 5.2) is proven here for free, before v0.8 puts
it in front of a real runtime.

> **Headline finding: the dev server contains the Worker Controller Instance (WCI)**, and
> its AWS SDK honours `AWS_ENDPOINT_URL` (the mechanism Temporal documents for testing
> Lambda Serverless Workers with LocalStack). With a 200-line local stand-in for the two
> AgentCore APIs it calls (`scripts/agentcore_emulator.py`), the **real WCI** of CLI 1.9.1
> / server 1.32.0 invokes our local AgentCore-shaped Worker: cold start on a new Workflow,
> and again when Finance's Nexus completion lands on a drained conversation (Q15,
> *locally*). Nothing leaves the laptop (dummy credentials, no shared AWS config,
> `require_role_and_external_id=false`). Consequence for v0.8: **the WCI-handshake tag is
> viable** (its precondition holds); it still needs go-ahead G5.

> **Live Bedrock: not run (justified deviation, same cause as v0.2–v0.6).** On 2026-10-29
> `aws sts get-caller-identity` still returns `InvalidClientTokenId`. v0.7 needs no model
> to prove its contract (every model turn is a scripted `invoke_model` Activity through
> the same plugin seam). Step 12 of the verify script is the live run (Case A through the
> WCI on Opus 5.5); ledger 49 carries it with the earlier live items.

## Which samples and docs it follows

- **samples-python `bedrock_agentcore/strands_agent/agentcore_worker.py`** (and its
  `tests/test_agentcore_worker.py`): the whole entrypoint shape is this sample's —
  `_worker` task as the single-start guard and strong reference, `add_async_task` →
  `create_task` → ack, `_run_until_idle` with `complete_async_task` in `finally`,
  `ActivityTracker`/`_TrackedActivity` interceptor with an `asyncio.Event`, `async with
  worker: await tracker.wait_until_idle(DEBOUNCE)`, `DRAIN = 120 s`, thread pool for sync
  Activities, `TEMPORAL_DEPLOYMENT_NAME`/`TEMPORAL_BUILD_ID`/`TEMPORAL_TASK_QUEUE` env
  names, Build ID required ("a defaulted build ID would silently strand Workflows"),

## Run it

```bash
make setup                                    # once
# A. "I am the WCI" (plan steps; offline)
make dev-server-up
make payments-mock &  make worker-finance-scripted &  make nexus-endpoint
make agentcore-local-scripted &               # :8080 (/invocations, /ping); `make agentcore-local` = Opus 5.5
make agentcore-ping                           # Healthy: no Worker yet
make invoke-local                             # lifetime 1 starts: HealthyBusy
make register-version MODE=--poller           # deployment create (if absent) + set-current-version
make case-b-serverless WF=support-2077-sl     # Case B on support-tq; Finance goes input-required
make agentcore-ping                           # Healthy again ~20 s later: the Worker drained
make approve WF=support-2077-sl APPROVER=dana.finance
temporal worker deployment describe-version -n agents --deployment-name support-supervisor \
  --build-id $(make -s build-id) --report-task-queue-stats   # workflow backlog 1, nobody polling
make invoke-local                             # lifetime 2 finishes the conversation
make result WF=support-2077-sl
uv run python scripts/serverless_report.py support-2077-sl    # 2 lifetimes, one Build ID, PINNED

# B. The dev server's own WCI does the invoking (offline; nothing reaches AWS)
make dev-server-down; make dev-server-up WCI=1
make agentcore-emulator &                     # the two AgentCore APIs the WCI calls -> :8080
make register-version                         # MODE=--local-wci: create-version / update-version-compute-config
make case-b-serverless WF=support-2077-wci    # no invoke-local: the WCI starts the session
make approve WF=support-2077-wci APPROVER=dana.finance   # the Nexus completion wakes the WCI again
make wci-history                              # task-add-signal -> InvokeWorker, per invocation
# Packaging
make agentcore-bundle agentcore-bundle-test
```

**What to look at.**
- `/ping` flips `Healthy` → `HealthyBusy` on invocation and back ~20 s after the last
  Activity. The app log prints one line per lifetime: polling → idle → drained → released.
- Web UI, namespace `agents`, `support-2077-sl`: Workflow Tasks before and after the wait
  carry different Worker identities (`…/agentcore-lifetime-N`), the same
  `support-supervisor:<build>`, behaviour **Pinned**. "Workers → Deployments" shows
  `support-supervisor` with the current version.
- The WCI is an ordinary system Workflow you can open by ID:
  `temporal workflow show -n agents -w temporal-sys-worker-controller-instance:support-supervisor:<build>`.

## Talk track

"Support's Worker is now built to die. It starts when invoked, works, notices it's idle,
drains and exits. Here Finance is waiting for a human, so Support has nothing to do: twenty
seconds later the Worker is gone and the session reports Healthy. When Finance answers, a
new invocation picks the conversation up, pinned to the exact build it started on. For the
first half I'm the one invoking it, with curl. And then a surprise: the Temporal dev server
already contains the Worker Controller, so with a tiny stand-in for the two AgentCore APIs
it calls, Temporal itself starts the Worker, including when Finance's answer arrives on a
conversation nobody is serving."

## Deviations and decisions

- **Live Bedrock not run** (AWS SSO session expired). Step 12 is the live run; ledger 49.
- **Local WCI through an emulator, beyond the plan.** The plan's "I am the WCI, with curl"
  is built and verified (Part A). Part B adds `scripts/agentcore_emulator.py` (named for
  what it is, instead of the plan's optional `fake_wci.py`: the WCI is real, the AgentCore
  APIs are fake). It never touches AWS: `WCI=1` sets dummy credentials, `AWS_CONFIG_FILE=/dev/null`
  and `require_role_and_external_id=false`; versions use
  `--aws-agentcore-skip-role-and-external-id` (the runbook says never to use it *against
  real AWS*; locally it is the only option, like Temporal's LocalStack guide). The endpoint
  ARN carries a placeholder account built at run time (no 12-digit literal in git).
- **Flat bundle** (`support_agent/` at the code-location root, not under `src/`), so the
  entrypoint imports without path tweaks; same as the sample's layout.
- **The versioned queue is `TEMPORAL_TASK_QUEUE`** (default `support-tq`), not
  `SUPPORT_TASK_QUEUE` (which `.env` points at the dev queue).
- **`create-version`/`update-version-compute-config` invoke the runtime**, which starts one
  Worker lifetime with nothing to do (it drains after the debounce): expected, visible as
  "lifetime 3 … 0 activities" in step 10.
- **The WCI sometimes invokes again while a Worker is polling** (03:19:50.9, 1.7 s after the
  conversation ended); the single-start guard answers "worker already polling". This is
  why the guard exists (runbook 5.2).
- **Debounce counts Activities only** (as the sample). A turn always contains an Activity
  (`invoke_model`), so a turn is never cut; the window starts at Worker start, so a Worker
  invoked with nothing to do lives one debounce.
- **Flaky test seen once** (pre-existing): `test_caller_budget_shorter_than_finance_wait_is_a_nexus_timeout`
  (a 2 s Nexus budget) failed once in a full run while the machine was busy and passed in
  isolation and in two further full runs. Not changed; noted for the verifier.
