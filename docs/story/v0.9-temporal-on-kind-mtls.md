# v0.9-temporal-on-kind-mtls: the real server on the laptop, then zero trust on the wire

**Goal.** Replace the dev server with the official Helm chart (`temporal-1.7.0`, server
images **1.32.1**) on a local kind cluster, with the values set EKS will reuse; run Finance
and payments-mock in the cluster like on EKS, Support on the laptop in AgentCore shape
through a port-forward; then rebuild the cluster with **mTLS everywhere** from a free
cert-manager CA (runbook 2.6) and run Cases A and B again (gate **G3**).

**Why now.** It freezes `values.base.yaml`, `values.tls.yaml` and the kustomize base that
v0.11 reuses on EKS, while reinstalling is free (about two minutes for a fresh cluster
with the server). Chart and certificate questions get answered here, and arm64 kind
proves the arm64 images the Graviton nodes need.

> **v0.8-wci-handshake was skipped in this run.** It needs AWS resources (IAM roles, the
> CFN invocation-role stack, a PUBLIC AgentCore runtime) and go-ahead G5, and the AWS SSO
> session has been expired since v0.2. Its items stay open in the ledger and move to v0.12
> / v0.13 (plan §7: "if v0.8 is skipped ... its items move to v0.12 and v0.13"). The
> optional Secrets Manager path of this tag was skipped for the same reason (no AWS
> resources); the code path (`support_agent.mtls`, `scripts/export-agentcore-cert.sh`)
> exists and is unit-tested, the script refuses to run without
> `EXPORT_AGENTCORE_CERT_CONFIRM=yes`.

> **Live Bedrock: not run (justified deviation, same cause as v0.2–v0.7).** On 2026-10-30
> `aws sts get-caller-identity` still returns `InvalidClientTokenId`. Nothing in v0.9
> depends on the model: the cluster, certificates, NetworkPolicy and both Cases run with
> the scripted models bound to the same `"bedrock"` key (Finance in the cluster: image
> target `finance-scripted`; Support: `make agentcore-local-scripted`). Verify step C is
> the live run (`make kind-aws-creds kind-workers FINANCE_MODEL=bedrock`, `make
> agentcore-local`); ledger 49 carries it.

## Which samples and docs it follows

- **temporal-developer skill**: `python/python.md` (envconfig: `ClientConfig.load_client_connect_config()` + `setdefault`, no TLS in code), `core/dev-management.md` ("Dev to Prod": only the connection descriptor changes, a profile per environment, smoke with `temporal ... --profile`), `python/gotchas.md` + `sync-vs-async.md` (Finance's sync Activities stay on the thread pool; the shutdown path does not block the loop), `python/testing.md` (`start_local` shared env, unique task queue per test, every wait bounded), `core/troubleshooting.md` ("Worker Not Starting": connection/TLS checks used for the negatives).
- **samples-python `hello/hello_mtls.py`**: the three TLS inputs (server root CA, client cert, client key) and the server name. We pass them through envconfig (`TEMPORAL_TLS_*_PATH` / the `kind` profile) instead of `TLSConfig(...)` in code, so one code path serves local, kind and EKS.
- **samples-python `env_config/`** (`config.toml`, `load_profile.py`): `[profile.<name>]` + `[profile.<name>.tls]` with `client_cert_path` / `client_key_path`; the `kind` profile is that shape plus `server_ca_cert_path` and `server_name`.
- **samples-python `gcp/cloud_run/`**: `Dockerfile` (uv sync into `/app/.venv` in a builder, slim runtime, non-root user) for the Finance image; `worker.py` (SIGTERM/SIGINT → `loop.create_task(worker.shutdown())`, `graceful_shutdown_timeout`) for `run_until_signalled`.
- **samples-python `hello_nexus/handler/worker.py`, `strands_plugin/tools/run_worker.py`**: the Finance Worker is unchanged (Workflows + Nexus handler + pinned StrandsPlugin); only how it is packaged, connected and stopped changed.
- **samples-python `bedrock_agentcore/strands_agent`, `worker_versioning`**: Support on the laptop is v0.7's AgentCore-shaped Worker; `register-version --poller` as before.
- **Temporal docs** (docs MCP tool): "Client environment configuration reference › TLS variables" (`TEMPORAL_TLS`, `_CLIENT_CERT_PATH`, `_CLIENT_KEY_PATH`, `_SERVER_CA_CERT_PATH`, `_SERVER_NAME`; ledger 34), "Temporal Service configuration reference › tls" (internode cert is the client cert of every role; internode EKUs none or both), "Web UI environment variables › TLS" (`TEMPORAL_TLS_CA/CERT/KEY/SERVER_NAME/ENABLE_HOST_VERIFICATION`, what `web.tls` sets), "Python › Temporal Client › Connect" (`TLSConfig` is static for a `Client`'s lifetime; rotate by connecting a new client and assigning `worker.client`: Q18), server release notes 1.9.0 ("periodic refreshing of TLS certificates from files": Q10).
- **Chart temporal-1.7.0 source** (`helm pull --untar`): `templates/_helpers.tpl` (`temporal.server.tls.config`: `clientCaFiles` = `<frontend mount>/ca.crt` only; `temporal.adminClient.tls.*`: admintools, the namespace Job and the helm test mount the **frontend** Secret as their client cert), `server-dynamicconfigmap.yaml` / `server-deployment.yaml` (`checksum/config` covers the server ConfigMap only: dynamic config reloads without a rollout), `server-job.yaml` (the schema Job mounts `admintools.additionalVolumes`, not `server.additionalVolumes`), `values/values.tls.yaml` and `ci/postgres-tls-values.yaml` (cert-manager + `requireClientAuth`), `server-pdb.yaml` (per-component `podDisruptionBudget`).

## Run it

```bash
make setup                                      # once; make tools for kubeconform
make dev-server-down                            # 127.0.0.1:7233 must be free

# commit-1 shape: the chart without TLS
make kind-up kind-temporal KIND_TLS=0           # helm template | kubectl apply --dry-run=server, then install
make kind-workers KIND_TLS=0 FINANCE_MODEL=scripted
make pf TEMPORAL_PROFILE=kind-plaintext         # frontend :7233, UI http://127.0.0.1:8233
TEMPORAL_PROFILE=kind-plaintext make nexus-endpoint
make kind-down

# commit-2 shape: a fresh cluster, mTLS in the first install's values
make kind-up kind-temporal                      # postgresql + base + tls + kind
make kind-workers FINANCE_MODEL=scripted        # or: make kind-aws-creds kind-workers FINANCE_MODEL=bedrock
make certs-pull pf
export TEMPORAL_PROFILE=kind
temporal operator namespace list                # operator cert, Route 53 server name
make nexus-endpoint
make agentcore-local-scripted &                 # Support on the laptop, agentcore-worker cert
make invoke-local register-version MODE=--poller
make case-a-serverless task-state WF=support-1042-sl     # handled_by: a kind pod
make case-b-serverless WF=support-2077-sl       # input-required; kubectl delete one Finance pod
make approve WF=support-2077-sl APPROVER=dana.finance
make invoke-local result WF=support-2077-sl
make cert-renew NS=temporal CERT=temporal-frontend-tls   # rotation drill (Q10)
make kind-down                                  # leaves nothing behind
```

kubectl by hand: `eval $(make -s kind-env)`. Optional `/etc/hosts` line
`127.0.0.1 temporal-frontend.temporal-customer-support.internal` lets you dial the Route
53 name itself; it is not needed (the `kind` profile dials 127.0.0.1 and checks that name).

**What to look at.**
- `make kind-status`: every Temporal pod on `temporalio/server:1.32.1`, all Certificates
  `READY=True`, two Finance pods.
- Web UI (`make pf`, http://127.0.0.1:8233), connected over `web.tls` with its own client
  cert: namespace `agents` → `support-2077-sl` → the Nexus operation to `finance-agent`;
  namespace `agent-services` → `a2a-task-support-2077-sl`, its `issue_refund` Activity
  ran on a pod whose name is in the `refund_confirmation` artifact.
- `kubectl get cm temporal-dynamic-config -n temporal -o yaml`: the WCI keys with
  `constraints: {namespace: agents}`.

## Talk track

"Same code, real server: the official Helm chart on 1.32.1, with the values we'll use on
EKS, and Finance running in the cluster next to its payments system. Then we rebuild it
locked down. One free CA inside the cluster issues everything: the server's certificates
and one client identity per kind of Worker. No certificate, the wrong CA, plain text, the
wrong server name: all refused. Finance dials the service name, Support dials the Route 53
name through a tunnel, and a pod without the right label can't even open the port. I
rotate the frontend's certificate while it's serving and nothing restarts. And the A2A
contract still hasn't changed."

## Decision (G2)

- **Q15 status:** v0.8 was skipped, so there is no AWS answer. The only evidence is v0.7's
  local first look (the dev server's WCI was woken by Finance's Nexus completion and
  invoked the emulator). Status: **plausible, not known on AWS**.
- **AWS spend:** v0.10 onwards creates standing infrastructure. It starts **only on the
  user's explicit go-ahead (G5)**; nothing in this run created, changed or deleted an AWS
  resource. The user has accepted the demo sizing (ADR-0006).
- **Pre-wired Q15 fallback:** keep the 30 s cloud debounce (ADR-0006) and, if v0.13 shows
  that a Nexus completion does not wake the WCI, add the nudge (a tiny Workflow task on
  `support-tq` after `approve`, the runbook's first fallback) rather than a long debounce
  (which costs AgentCore session time). Recorded in ledger 67; v0.13 decides.
- **G3:** passed (Case B over mTLS on kind).

## Deviations

- **v0.8 skipped** (AWS resources, G5) and the **optional Secrets Manager path** skipped.
- **Live Bedrock not run** (expired SSO session; ledger 49; verify step C).
- **Frontend cert usages** include `client auth` (chart requirement; everything else in
  runbook 2.6 is verbatim).
- **Two commits by layer, not "plaintext" then "mTLS":** both shapes live in the final
  tree (`KIND_TLS=0|1`) and the verify script rebuilds both from scratch, so the history
  holds one feature commit and one docs commit.
- **`/etc/hosts` not edited** (no sudo): the `kind` profile dials 127.0.0.1 and checks the
  Route 53 name via SNI/SAN, which proves the same certificate path.
- **`cmctl` not installed**: `scripts/cert-renew.sh` sets the same `Issuing` condition with
  `kubectl patch --subresource=status`. kubeconform comes from `make tools` (no brew).
- Laptop Support uses the **AgentCore Worker identity** (`agentcore-worker`) for the
  AgentCore-shaped app and `laptop-support` for the unversioned dev Worker.
