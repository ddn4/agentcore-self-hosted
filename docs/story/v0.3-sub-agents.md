# v0.3-sub-agents: Support's own team of agents, used as tools

**Goal.** Order Lookup and Return Policy become Support-owned **sub-agents**. Each
is a `TemporalAgent` called from an in-workflow Strands `@tool`. The Supervisor
uses runbook 5.6's `SUPERVISOR_PROMPT` without the Finance part, and its only
tools are the two sub-agents.

**Why now.** This is composition *inside one team*: same Workflow, same
namespace, same Worker, in-process. It sets up the contrast for v0.4 and v0.5,
where the next agent belongs to someone else and is reached over Nexus.

## Which samples and docs it follows

- **samples-python**
  - `strands_plugin/tools/workflow.py` and its README: the three tool kinds. A plain
    `@tool` runs **in Workflow context** (our `order_lookup_agent` /
    `return_policy_agent`), and `activity_as_tool` is for I/O (the sub-agents'
    `lookup_order` / `get_return_policy`). The agent is built in the Workflow and
    run with `invoke_async`.
  - `bedrock_agentcore/strands_agent/workflows.py`: system-prompt constants,
    Activities imported through `imports_passed_through()`, `invoke_async` and
    never the sync call.
  - `strands_plugin/hooks/workflow.py`: in-workflow callbacks must be
    deterministic and do only pure data manipulation. Our tools only build an
    agent and await it, and `record()` appends to Workflow state.
  - `strands_plugin/human_in_the_loop`: the query-over-Workflow-state idiom
    (`sub_agent_runs`).
  - `tests/strands_plugin/tools_test.py` / `_mock_model.py`: plugin appended via
    `client.config()`, `max_cached_workflows=0` to force replay, and the scripted
    stream-event shapes.
  - No sample covers nested Strands agents (Q20 is exactly that gap). The closest
    doc is the OpenAI Agents integration's "Nested agent tools" (`Agent.as_tool()`
    works unchanged there). The Strands equivalent does **not** carry over cleanly
    (see Q20 below).
- **temporal-developer skill**
  - `gotchas.md`: Workflows and Activities in separate files, pass-through
    imports, test failure paths (failing sub-agent, unknown order), and test
    replay. `asyncio.sleep` in a Workflow is a durable timer, which is the root of
    the `as_tool()` finding.
  - `determinism.md` / `determinism-protection.md`: sandbox pass-through for
    third-party modules (`strands` in `agents.py`).
  - `testing.md`: time-skipping vs `start_local` (the `as_tool` probe needs real
    time), unique queues and IDs, `Replayer` over JSON histories.
  - `versioning.md`: the change is incompatible with v0.2 histories. Patching was
    not used, because the dev queue is unversioned and drained, and v0.7 brings
    PINNED Worker Versioning. The v0.2 fixture asserts the `NondeterminismError`.
  - `ai-patterns.md`: Temporal owns retries (bounded model `RetryPolicy` on every
    agent), and prompts are versioned in code.
  - `patterns.md`: queries.
- **Temporal docs** (docs MCP): *Strands Agents integration* (`invoke_async` not
  `agent(...)`; `@tool` runs in Workflow context; `activity_as_tool` options);
  *OpenAI Agents SDK integration → Nested agent tools* (the pattern we wanted); the
  *Multi-agent ADK cookbook* (per-agent `summary` on the model Activity for
  attribution, the same idea as our `summary=<agent name>`).
- **Installed source** where docs were thin:
  - `temporalio/strands_agents/_temporal_agent.py` (`summary` and activity options
    go to `TemporalModel`).
  - `_temporal_model.py` (`summary` is passed to `execute_activity_method`, and
    so stored as `user_metadata.summary` on `ActivityTaskScheduled`).
  - `workflow.py` (`activity_as_tool`, which has no summary by default).
  - `strands/agent/agent.py` (`invoke_async`/`stream_async`, the
    `_concurrency` lock, `_start_cancel_watcher` / `_link_cancel_signal` polling
    `asyncio.sleep(0.05)`).
  - `strands/agent/_agent_as_tool.py` (`as_tool()` forwards the parent's
    `cancel_signal`, uses `threading.Lock`, and resets state per call).
  - `strands/tools/decorator.py` (a `@tool` turns `Exception` into an error tool
    result; `CancelledError` passes through).

## Decisions and deviations

- **Hand-written `@tool`, fresh `TemporalAgent` per call** (ADR-0003). A sub-agent
  is a stateless lookup, so every question starts from an empty conversation,
  which is the same as `as_tool(preserve_context=False)`. Building an agent does
  no I/O, so it is Workflow-safe.
- **The Supervisor no longer calls the data Activities directly.** The sub-agents
  own them. Seven model calls per case instead of three, which is acceptable for
  the demo and makes the team visible.
- **`strands` imported through `imports_passed_through()`** in `agents.py` (runbook
  5.6 does this too). Found by `make check`: the v0.1 hello tests build a Worker
  without the StrandsPlugin, and sandbox validation of a module that imports
  `strands` then fails on `urllib3`/`http.client`.
- **Sub-agent failure is a tool error, not a Workflow failure.** Strands catches
  `Exception` from a `@tool`; cancellation (`CancelledError`) still propagates.
- **Breaking change vs v0.2 histories, no patch.** The dev queue is unversioned and
  the verify script checks there are no open runs. `tests/histories/v0.2/` and
  `test_v02_history_does_not_replay_on_v03_code` record the
  `NondeterminismError`. Worker Versioning (v0.7) is the real answer.
- **The `as_tool` probe runs on the dev server, not time-skipping**, because its
  timers advance virtual time during the model Activity.
- **The scripted fixtures are dev-server recordings of the real Workflow code with
  a scripted model.** The plan asked for a live re-recording, which is pending on
  AWS. `RECORD_HISTORY=1` re-records both the scripted and the live fixtures.
- `scripts/verify/v0.2-durable-agent.sh` checks the v0.2 Workflow shape, so it only
  passes from a `v0.2-durable-agent` checkout. Its live steps were moved into the
  v0.3 script (steps 6–7). `VERIFY_SKIP_CHECK=1` exists only to bootstrap
  fixtures that `make check` itself replays.
