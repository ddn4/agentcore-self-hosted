# v0.11-temporal-and-finance-on-eks: the real server on AWS, then Finance next to it

**Goal (plan v0.11).** *Commit 1, server:* the official chart (`temporal-1.7.0`, server
**1.32.1**) on the v0.10 EKS cluster with the **same values as kind** plus one EKS file: RDS
PostgreSQL over TLS with the RDS CA and host verification, 512 shards, the frontend behind an
**internal TCP NLB** (ip targets, TLS passed straight through) at the private name
`temporal-frontend.temporal-customer-support.internal`, IRSA (`temporal-server-wci`) on the
worker service only. *Commit 2, Finance:* the Finance agent and payments-mock on EKS from ECR
(arm64), with their own IAM identity, the Nexus endpoint, and a **hybrid demo**: Support still
runs on the laptop (plain Worker on `support-dev-tq`, `laptop-support` certificate, through a
port-forward) and calls Finance on EKS over Nexus. Gate **G4**: hybrid Case B passes.

> **Status: done (2026-10-31).** Applied in us-east-1 (user go-ahead for v0.11–v0.13) and **left
> running** for v0.12. `scripts/verify/v0.11-temporal-and-finance-on-eks.sh`: **OK**; `make check`
> green. Nothing in the v0.10 foundation was paused, destroyed or recreated. The laptop Support
> Worker and the port-forwards are stopped. Build ID unchanged: **`fd7af7a`**.

## Why now

Every behaviour, value and certificate was proven on kind (v0.9) and the AWS foundation exists
(v0.10). This tag changes the backend only ("same values, different backend") and proves the
EKS side of runbook 7b.9 before AgentCore: the handler on EKS, IRSA Bedrock access, the
NetworkPolicy, the NLB path. It also shows the two teams deploying independently: Finance ships
an image and an overlay; Support has not moved.

## Run it

```bash
make render-config eks-kubeconfig                      # v0.10 outputs -> .generated/
# commit 1: the server
make eks-rds-ca                                        # namespace temporal + Secret rds-ca (official bundle)
make create-db-user                                    # temporal_user; password -> Secrets Manager + k8s Secret
make rds-snapshot CHANGE=v011-install                  # before the first install (runbook Phase 11)
make eks-temporal                                      # certs, values, dry-run=server, install --timeout 900s (~2 min)
make route53-alias                                     # temporal-frontend.temporal-customer-support.internal -> NLB
make certs-pull pf TEMPORAL_PROFILE=eks-pf             # .certs/eks/, frontend :7233 + UI http://127.0.0.1:8233
export TEMPORAL_PROFILE=eks-pf; eval "$(make -s env)"
temporal operator namespace list                       # agents, agent-services, default, temporal-system
# commit 2: Finance
make finance-image finance-deploy                      # arm64 -> ECR; 2 Finance pods + payments-mock
make nexus-endpoint card                               # endpoint finance-agent; Q16: standalone get_agent_card
make worker-support SUPPORT_TASK_QUEUE=support-dev-tq &   # laptop Support (real Opus 5.5), laptop-support cert
make case-a WF=support-1042-eks task-state WF=support-1042-eks
make case-b WF=support-2077-eks; make pending WF=support-2077-eks
make approve WF=support-2077-eks APPROVER=dana.finance; make result WF=support-2077-eks
make failure                                           # Finance 0 -> retries -> 2 -> completes
kill %1; make pf-stop                                  # stop the laptop Worker and the port-forwards
scripts/verify/v0.11-temporal-and-finance-on-eks.sh    # ~10 min; output already redacted
```

## Deviations

- **Extra NetworkPolicy and SG rule** beyond the plan's list: `temporal-frontend-from-nlb`
  (generated: the NLB ENIs' /32s; without it the targets stay unhealthy) and `nlb_from_nodes`
  (pods may use the NLB name for the in-VPC checks). Both are the minimum for the plan's own
  acceptance items.
- **Targeted apply:** the SG rule was applied with `-target`, because an untargeted plan now also
  rolls the node group to a newer AMI release that AWS published after v0.10 (ADR-0006 v0.11,
  ledger 69). The next full `make tf-plan STACK=20-platform` will show that node group update.
- **The `temporal_user` role has CREATEDB** so the chart's schema Job can create the databases
  (runbook 2.2's `createDatabase: true`, as on kind). Without it the script would have to create
  them as master.
- **Two NLB listeners:** the chart's frontend Service also carries the HTTP API port 7243, so the
  NLB has a 7243 listener; the SG admits 7233 only.
- **Snapshot name:** the first snapshot's stamp is `yyyymmddHHMM` (12 digits, which `redact.sh`
  reads as an account ID); `rds-snapshot.sh` now writes `yyyymmdd-HHMM`.
- **The verify script's first run failed in `make check`** because it had `source`d and exported
  `.generated/foundation.env`, leaking the real execution-role ARN into `test_vpc_render`; fixed
  twice (the script no longer exports it; the test clears the variables).
- **`handled_by`** is the artifact field the plan calls `handled_by_pod` (the name since v0.4).
- **UI:** port-forward only (runbook 2.8's "simplest option"); no `temporal-ui` record.
