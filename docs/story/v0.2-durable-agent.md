# v0.2-durable-agent: an LLM loop that survives a crash

**Goal.** A Support Supervisor `TemporalAgent` in namespace `agents`, with
`lookup_order` and `get_return_policy` as `activity_as_tool`, on a local
unversioned Worker on `support-dev-tq`. Kill the Worker mid-thought and the
conversation carries on from exactly where it stopped.

**Why now.** This is the core idea in its smallest form, and the cheapest place
to settle the plugin wiring, model pinning, effort, the Opus 5.5 constraints and
the offline test seam (ScriptedModel) before any Nexus or AgentCore code exists.

> **Status at tag: offline complete and verified independently; live Bedrock
> deferred (justified deviation).** The tag's verifier re-ran `make check`, the
> offline verify script and the demo commands from a clean machine, and added an
> offline wire test (`test_wire_offline.py`): the exact signed ConverseStream
> request the pinned model builds has the Opus 5.5 model ID in its path, an empty
> `inferenceConfig`, `toolChoice {"auto": {}}` and no `additionalModelRequestFields`
> at the default effort. What still needs Bedrock (the 400s, acceptance of
> `output_config.effort` at non-default levels, effort latency, a live
> `support-1042` history) is carried to ledger item 49 and must run at the start
> of v0.3; anything it breaks is fixed forward as `v0.2.1-…`.

## Decisions and deviations

- **Sync data Activities** with a `ThreadPoolExecutor` (skill default; file I/O
  blocks). `say_hello` stays async (no I/O).
- **Model Activity options:** `start_to_close_timeout=120s` (adaptive thinking
  cannot be turned off on Opus 5.5), `heartbeat_timeout=10s` (the plugin
  heartbeats every 5 s while the model streams; a dead Worker is noticed in ~10 s),
  `RetryPolicy(maximum_attempts=5, initial 1 s, max 20 s)`: bounded so a request
  the model refuses (400) fails the Workflow instead of retrying forever. Tool
  Activities: `start_to_close_timeout=10s`, default retries; unknown orders are
  non-retryable and reach the model as a tool error.
- **`summary="Support Supervisor"`** on the agent: every `invoke_model` is
  labelled in the UI (attribution for v0.3's sub-agents).
- **`callback_handler=None`**: Strands' default handler prints to stdout from
  inside the Workflow.
- **Effort not sent at `medium`**, so the default request is unchanged from v0.1's
  verified wire shape even before the live check.
- **Crash test filters `PytestUnraisableExceptionWarning`**: evicting a Workflow
  suspended inside Strands' agent loop lets Strands' async generators be
  garbage-collected outside their loop (`GeneratorExit` / `aclose()` noise).
  Harmless (state is in history); scoped to that one test.
- **Workers in the verify script run as `.venv/bin/python`, not `uv run`:** `uv
  run` keeps python as a child process, so `kill -9 $!` killed `uv` and orphaned
  the Worker (found while building the demo: the first run showed no retry).
- **`record_history.py` scrubs** `identity` fields and sticky task-queue names
  (`<pid>@<hostname>-<hex>` → `sticky-<hex>`); replay does not need them.
- `spikes/_wire.py` uses the plugin's private `_model_activity` module to run the
  real `invoke_model` Activity without a server (spike-only).

## Talk track

"This is an ordinary Strands agent: a system prompt, two tools, Claude Opus 5.5.
The difference is that every model call and every tool call is a Temporal
Activity. Here's the history: think, look up the order, think, read the policy,
answer. Now I kill the Worker with `kill -9` while the model is thinking. Start
it again, and it doesn't redo the order lookup or the first model turn: it
replays them from history and only retries the call that was in flight. Same
answer, nothing lost, and no checkpoint code in the agent."
